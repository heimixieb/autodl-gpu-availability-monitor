# AutoDL GPU Availability Monitor

一个帮你盯着 AutoDL GPU 什么时候空出来的浏览器扩展。

## 我为什么做它

我经常在 AutoDL 租服务器，最头疼的不是训练慢，而是明明实例已经租好了，却因为宿主机上的 GPU 被别人占着，暂时开不了机。

AutoDL 会在 GPU 空出来后显示一行绿色的“GPU充足”，问题是——谁有空一直刷新网页看它？

所以我做了这个小扩展。你只要告诉它想等哪台实例，然后把 AutoDL 页面留在浏览器里。GPU 一旦空出来，它就会弹窗、响铃，把你叫回来。

### 然后发现「只提醒」根本不够

用了一阵子发现：GPU 空出来那一刻弹提醒，等我看到、回到电脑前、点开机，**卡往往已经被别人抢走了**。抢卡是分钟级的竞争，光提醒等于没做。

于是加了两件事：

1. **自动开机**——GPU 空出的瞬间就替我把「开机」点掉，先把卡抢到手。代价是开机即开始计费。
2. **5 分钟没人确认就自动关机**——抢到卡之后给我 5 分钟回来点「我已回来」。点了 = 人在，继续用；5 分钟没点 = 没人在电脑前，实例在空跑烧钱，立刻关掉省钱。

第三条来自实际使用中暴露的问题：把浏览器放到后台，提醒就只剩声音；声音没开，我根本不知道发生过什么。所以又加了**系统级弹窗**——浏览器在后台也照样弹到桌面最前面。

## 它能做什么

- 同时盯住多台实例，名称或实例 ID 都可以
- GPU 空出来时弹出提示、发送系统通知并响铃
- **系统级置顶弹窗**：浏览器在后台、被别的窗口盖住时也会弹到桌面最前面，必须点按钮才消失
- 可以只响一次，也可以持续响到你回来
- 页面右下角会告诉你它有没有正常工作
- 识别出问题时可以一键复制诊断信息，方便反馈
- 可选自动开机：GPU 空出后由扩展代你点「开机」（默认关闭，会产生费用）
- 可选超时自动关机：自动开机成功后 5 分钟内没人点「我已回来」，自动关机，避免无人空跑计费

默认情况下它只负责提醒，**不会替你开机**。自动开机是一个可选的开关，默认关闭；只有你自己勾上之后，扩展才会在 GPU 空出时代你点「开机」，**这会产生真实费用**。

## 提醒会同时走三条路

只靠系统通知不够可靠：Windows 的「通知」总开关一旦被关掉（很多优化脚本会关），或者开了专注助手，浏览器调用 toast 不会报错，但系统会**静默丢弃**——你只剩声音，声音没开就等于什么都不知道。

所以关键提醒会同时走三条路：

| 通道 | 特点 |
| --- | --- |
| 页面右下角面板 | 只在 AutoDL 页面可见，适合你正开着浏览器时 |
| Windows 系统通知 | 会进通知中心留痕，但可能被系统开关或专注助手拦掉 |
| **系统级弹窗** | 扩展自己开的独立窗口，弹出时直接到最前、任务栏持续闪烁，浏览器在后台也看得到，必须点按钮才消失 |

弹窗不需要装任何东西、不改注册表、不要额外权限，是扩展用 `chrome.windows.create` 自己弹的。弹窗里有三种形态：

- **GPU 已空出**（绿色）：`静音` / `知道了` / `打开 AutoDL`
- **已自动开机、正在计费**（红色）：带 5 分钟倒计时和进度条，主按钮 `我已回来，继续使用`
- **自动关机结果**（成功蓝色 / 失败红色）：失败时主按钮变成 `打开 AutoDL 手动关机`

`Enter` 直接按主按钮，`Esc` 关窗。

**一个诚实的限制**：浏览器扩展拿不到真正的「窗口永远置顶」。`alwaysOnTop` 是 ChromeOS 专属属性，Windows/macOS 上 Chrome 和 Edge 会静默忽略（真机实测过）。所以实际行为是：**弹窗创建时抢一次焦点、直接盖到最前**，之后每 30 秒让任务栏按钮闪一次，直到你点掉它——不会打断你打字，但你不会漏掉。如果你需要窗口物理上永久压在所有程序之上，那得装一个原生小程序，本扩展没这么做。

默认策略是**只在你看不见页面面板时才弹**。具体判断是：浏览器窗口在前台、**并且**当前标签页就是 AutoDL 实例页 —— 两个条件都满足才算「你看得见」，否则一律弹窗。所以浏览器最小化、切到别的程序、或者只是切到别的标签页，都会弹。

可以在扩展弹窗的「系统级弹窗」里改成「每次提醒都弹出」或「只发系统通知，不弹窗」。弹窗里的 `测试系统级提醒` 按钮会强制弹一次，方便当场确认效果。

**如果点了「测试系统级提醒」没反应**：说明浏览器里跑的还是旧版后台脚本。改扩展文件后必须在扩展管理页点一次「重新加载」才会生效（`popup.html` / `popup.js` 是每次打开都读盘，但 service worker 不会自动换）。为了不让你猜，弹窗打开时会自动检查后台版本，不匹配就直接显示红框和 **「立即重新加载扩展」** 按钮，点一下即可。

## 自动开机（可选）

如果你不想半夜爬起来点开机，可以让扩展替你点一下。这个开关默认关闭，开启后会真的把实例开起来，也就真的开始计费。

怎么开（两处任选其一）：

- 点击扩展图标，在弹窗里勾选「GPU 空出后自动开机（会产生费用）」；
- 或者在 AutoDL 页面右下角的状态面板里勾选同一项。

触发条件（两个都满足才会动作）：

- 该实例当前是「已关机」状态；
- 页面上该行显示「GPU充足」，也就是确实有空闲 GPU 可以分配。

触发后扩展会点击该实例行里的「开机」按钮，并尝试确认随后的开机弹窗。点击后它继续观察，最多尝试 3 次；3 次之后实例仍是关机状态，就发一条系统通知「AutoDL：自动开机失败」，请你手动开机。

### 开机后 5 分钟内要确认，否则自动关机

自动开机成功（接口返回「开机中」或「运行中」）后，扩展会给你 **5 分钟** 回来确认：

- 页面右下角面板会出现红色按钮 **「我已回来：实例名（取消自动关机）」**，旁边显示剩余时间；
- 系统通知「AutoDL：已自动开机」也带一个 **「我已回来，继续使用」** 按钮；
- 系统级弹窗同样带 `我已回来，继续使用` 主按钮和倒计时；
- 三处任点一处即算确认，之后不会再自动关机。

**如果 5 分钟内没有确认**，扩展会自动点该实例行里的「关机」按钮、确认关机弹窗，再用实例接口回查状态（最多 3 次、间隔 15 秒）。关机成功后会再发一条「AutoDL：已自动关机」通知，并**自动关闭「自动开机」开关** —— 否则会出现「抢到卡 → 没人确认 → 关机 → GPU 又空出 → 再抢卡」的无限循环，反复产生费用。需要时重新勾选自动开机即可。

倒计时存在 `storage.local` 里，中途页面自动刷新也不会重置；但 **AutoDL 标签页不能关**，关掉后扩展就没法替你点「关机」了。

几点需要知道：

- **费用自负**：开机成功就开始按 AutoDL 的规则计费。自动关机只是"5 分钟没人确认"时的保底动作，不能替代你自己盯着账单。建议先确认自己的计费方式和余额。
- 不需要把页面放在前台，扩展不会移动鼠标；置顶提醒窗口弹出时会抢一次焦点，这是故意的——不抢你可能根本注意不到。
- 但 **AutoDL 标签页要保持打开**：不能关掉，也不能被浏览器丢弃。扩展会把该标签页标记为不可自动丢弃，并用 `alarms` 每 30 秒补一次检测，防止后台标签页的定时器被降频。
- 只想被叫醒、不想花钱的话，让这个开关保持关闭即可，行为和以前完全一样。
- 5 分钟确认倒计时期间扩展会暂停页面自动刷新，避免按钮在你要点时消失。

## 安装

1. 在 [Releases](../../releases) 下载最新 ZIP 并解压。
2. 打开浏览器的扩展管理页：Chrome `chrome://extensions`、Edge `edge://extensions`、Arc `arc://extensions`。
3. 打开“开发者模式”，选择“加载已解压的扩展程序”。
4. 选中刚才解压出来的文件夹。

装好后，打开 AutoDL 的“容器实例”页面并刷新。点击扩展图标，填入想监控的实例名称或 ID，保存就可以了。

## 使用时需要知道

目前扩展是通过 AutoDL 实例页面判断状态的，所以浏览器要保持运行，并留着这个页面（放在后台就可以，不用切到前台）。它不会读取你的密码、Cookie 或登录令牌，也不会把实例信息发送给我。自动开机同样只是点击页面上已有的「开机」按钮，不涉及任何登录凭证。

如果右下角显示“识别异常”，先检查实例名称是否完全一致；还不行的话，点一下“复制诊断”，然后来 [提个 Issue](https://github.com/Kenny-Huang-mz/autodl-gpu-availability-monitor/issues)。请不要在 Issue 里粘贴 Cookie 或登录令牌。

## 最后
